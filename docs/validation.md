## 재현

```bash
make test
make integration
```

`make integration`은 Docker 이미지를 빌드하고 18080 포트의 `ssh-logger-test` 프로젝트에서 합성 데이터로 검사한다. Linux host networking을 사용하며 테스트가 끝나면 해당 프로젝트의 컨테이너·네트워크·볼륨을 제거한다. 기존 운영 프로젝트의 볼륨을 사용하지 않는다. 이 프로젝트 이름과 포트는 테스트 전용으로 예약해야 한다.

백업·복원 CLI는 테스트 서비스가 실행 중일 때 `COMPOSE_FILE=tests/compose.yaml`을 지정하여 검증했다. 운영 서비스 복원은 자동 테스트에 포함하지 않는다.

## 배포 환경에서 확인할 항목

1. Ubuntu 24.04 x86_64 및 ARM64에서 OpenSSH/PAM 감사 로그가 실제로 생성되는지 확인.
2. 개인 계정의 공개키·비밀번호 로그인 성공, 잘못된 계정·비밀번호·공개키 인증 실패 확인. 실패 수는 고유 로그인 시도 수가 아니라 SSH·PAM 감사 실패 기록 수다.
3. 새 SSH 세션에서 `id`, `sudo id`, 비대화형 `ssh host command` 실행 후 로그인 UID·실행 UID·세션 연결 확인.
4. 정상 로그아웃, 네트워크 단절, sshd 재시작, 호스트 재부팅 후 현재 세션과 확인 불가 상태 표시 확인.
5. 기존 감사 제외 규칙과 immutable 설정을 확인하고, 실제 auditd 로그 회전·압축 정책 아래에서 수집기 재시작과 전송 지연 확인.
6. 중앙 서버 HTTPS 인증서와 origin, 방화벽, 수집 토큰 교체 검증.
7. 실제 초당 이벤트 수와 30일 예상 데이터양을 기준으로 저장 지연·검색 속도·큐 및 WAL·백업 디스크 용량 측정.

Linux 커널 감사 기능은 일반 컨테이너만으로 독립된 호스트처럼 검증하기 어렵다. 개발 과정에서 호스트의 audit 규칙이나 SSH 설정을 변경하지 않았다.

## 현재 구현의 경계

- 터미널 녹화·출력 저장과 알림은 범위 밖이다. 관리자별 서버 권한은 아래 추가 검증 항목을 참고한다.
- Linux audit가 제공하는 SSH 이벤트를 읽으므로 감사 지원이 없거나 필터링된 환경에서는 접속 기록이 누락될 수 있다.
- 최초 설치 이전 기록과 이미 열린 세션의 시작 정보는 가져오지 않는다.
- local loginuid가 있는 실행도 감사 규칙에 포함된다. SSH 세션 연결 근거가 없는 실행은 연결 불명으로 표시한다.
- 서버 계정명은 수집기에서 UID를 조회한다. 외부 계정 디렉터리 등 로컬 조회가 안 되는 환경에서는 숫자 UID가 표시될 수 있다.
- 손실·공백 카운터는 정확한 총 손실 이벤트 수가 아니다. 큐 포화 손실과 복구 불가능한 읽기 공백을 함께 센다.
- 중앙 서비스는 단일 인스턴스다. 대량 이벤트, 장기 보관, 여러 API 인스턴스 요구는 별도 부하 검증과 설계가 필요하다.
