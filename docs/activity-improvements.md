# 활동 기록 개선안

## 현재 적용한 개선

기본 화면은 주요 활동을 표시하고, 전체 기록·보조 실행으로 전환할 수 있다. 알려진 환경 조회와 문자열 처리의 정확한 프로그램·인자 조합만 보조 실행으로 분류한다. 실패, 결과 불명, 로그인 계정과 실행 계정이 다른 실행은 주요 활동에 남긴다. 분류는 조회 단계에서 수행하므로 저장된 기록을 삭제하지 않고 기존 기록에도 적용된다.

긴 명령은 펼쳐서 확인한다. 새 수집기는 audit 레코드의 PID와 부모 PID를 전송한다. 기존 기록이나 해당 필드가 없는 레코드는 미수집으로 표시한다. 부모 프로그램명이나 사용자가 직접 입력한 명령으로 추정하지 않는다.

## 다음 단계 제안 — 아직 미구현

| 우선순위 | 개선 | 화면과 효과 | 필요한 조건 |
| --- | --- | --- | --- |
| 1 | 부모 프로세스별 묶기 | `lsb_release -a` 아래의 `getopt`, `tr`, `cut`을 하위 실행으로 펼치기 | 서버·부팅·시각·PID/PPID를 함께 사용하고 부모 연결 근거가 부족하면 미확인 유지 |
| 2 | 반복 실행 요약 | 동일 실행을 횟수, 최초·최근 시각으로 요약하고 원본 펼치기 | 같은 서버·세션·계정·권한·프로그램·인자·결과 및 제한된 시간 구간 안에서만 묶기 |
| 3 | 관심 활동 필터 | 인증 실패, 권한 변경, 서비스 관리, 파일 삭제 관련 실행을 빠르게 조회 | 프로그램과 인자를 근거로 분류하되 실제 작업 성공이나 악성 행위로 단정하지 않기 |
| 4 | 수집·검색 상태 표시 | 수집 지연, 큐 적체, 연결 불명 비율, 검색 응답 시간을 확인 | 지연 수집과 실제 활동 발생 시각을 구분하고 일별 수집량 측정 |
| 5 | 직접 입력 명령 별도 수집 | 사람이 셸에 입력한 명령과 하위 프로그램 실행을 함께 보기 | 별도 셸 연동 설계가 필요하며 내장 명령, 비대화형 실행, 우회·누락, 비밀 인자를 고려 |

먼저 PID·PPID 데이터를 쌓고 부모 연결 가능 비율을 측정한 뒤 1번과 2번을 진행하는 것을 권장한다. PID는 재사용되며 부모가 수집 시작 전에 실행됐거나 종료됐을 수 있다. 현재 `/proc`의 같은 PID를 과거 부모로 연결하면 안 된다. 정확한 프로세스 수명 추적이 필요하면 시작·종료 이벤트와 프로세스 식별 정보를 추가 수집해야 한다.

## 현재 로그에서 확인할 점

- 제공된 기록에는 셸 스냅샷 생성 명령과 환경 조회가 함께 있다. 반복되는 보조 실행의 출처를 확인할 단서지만 모든 `tr`·`cut`이 해당 작업의 자식이라고 확정할 수는 없다.
- `연결 불명`은 SSH 세션 연결 근거가 부족하다는 뜻이다. 동일 계정이나 가까운 시각만으로 다른 세션에 붙이지 않는다.
- 주요 활동은 사용자가 직접 입력한 명령 목록이 아니다. 정확히 일치하는 명령을 직접 실행해도 보조 실행으로 분류될 수 있으므로 전체 기록을 항상 제공한다.
- 페이지 필터는 서버에서 페이지 분할 전에 적용한다. 보조 실행이 앞 페이지를 채워 주요 활동이 사라지는 문제를 방지한다.
- 현재 요약 집계는 검색 범위의 기록을 평가한다. 운영 데이터로 지연을 측정하고 증가하면 분류 결과 저장·인덱스 및 집계 방식을 검토한다.
