# SSH Logger 1차 개발 스펙

확정일: 2026-09-11

## 목적과 상태

Linux 서버의 SSH 접속 및 프로그램 실행 기록을 중앙 관리자 웹 화면에서 조회한다. 이 문서는 사용자와 합의한 1차 범위와 기술 구성을 기록한다. 중앙 API, 관리자 화면, SQLite 저장, Linux 수집기 및 배포·관리 명령을 구현했다. 로컬 자동 검증과 실제 커널 감사 환경의 검증을 구분하며 상세 상태는 [검증 문서](validation.md)에 기록한다.

## 기술 구성

| 영역 | 확정 구성 |
| --- | --- |
| 서버 수집기 | Go, systemd 서비스 |
| 중앙 API | Go, 표준 net/http, HTTPS JSON REST API |
| 데이터베이스 | SQLite, WAL 모드, 중앙 서버 로컬 SSD |
| 프론트엔드 | React, TypeScript, Vite, Tailwind CSS |
| 중앙 서비스 배포 | Docker Compose, DB 영구 볼륨 |
| 저장소 구조 | agent/, server/, web/, deploy/, docs/ |

중앙 API는 한 인스턴스로 운영한다. 각 수집기는 HTTPS로 중앙 API에 전송하며 DB 파일에 직접 접근하지 않는다. SQLite 파일은 네트워크 공유 파일시스템에 두지 않는다. 의존성 버전은 구현 시 지원 상태를 확인하여 고정한다.

## 기능 범위

- 관리자 로그인과 로그아웃.
- 전체 현황: 현재 SSH 세션, 오늘 접속 수, 로그인 실패 수, 서버별 수집 상태.
- 접속 기록: 서버, 계정, IP, 시간, 성공/실패 및 세션 종료 정보 검색.
- 실행 기록: 실행 프로그램과 인자, 서버, 계정, 시간별 검색.
- 세션 상세: 접속 정보와 연결된 실행 기록을 시간순으로 표시.
- 원래 로그인 계정과 실행 계정을 구분하여 sudo 등 권한 변경을 표시.
- 서버 등록, 서버별 수집 토큰 발급·폐기, 수집 상태 및 마지막 수신 시각 표시.
- 기본 30일 보관, 보관 기간 설정 및 자동 삭제.
- 백업 및 복원 절차 제공.

터미널 출력 저장·재생, 실시간 터미널 보기, 알림, 관리자별 권한 분리, 외부 장기 저장은 후속 범위다.

## 수집 의미와 제한

SSH 인증 로그와 세션 정보를 수집하고, auditd를 활용해 SSH 세션에 연결되는 프로그램 실행과 인자를 수집한다. 감사 이벤트 여러 레코드를 하나의 실행 이벤트로 조합해야 한다. 세션 연결 근거가 부족한 기록은 연결 불명으로 표시한다.

프로그램 실행 기록은 터미널 입력 원문과 다르다. 셸 내장 명령, 리다이렉션 문법, 터미널 출력은 이 범위에 포함되지 않는다. 실행 감사 기록만으로 프로그램 종료 결과나 명령 성공 여부를 단정하지 않는다.

공용 계정은 개인을 확정 식별할 수 없으므로 계정과 접속 IP 수준에서 표시한다. 서버 관리자 권한으로 수집을 중단할 수 있으므로 완전한 변조 방지를 보장하지 않는다. 기존 서버의 감사 정책과 공존하도록 설치를 설계한다.

## 전송 및 상태

- 최대 5초 간격으로 이벤트를 묶어 전송한다.
- 수집기는 정상 연결 시 최대 5초마다 상태를 보고한다(초기 계획의 15초보다 빈번). 60초 이상 미수신이면 연결 이상으로 표시한다.
- 화면은 5초 간격으로 조회한다.
- 연결 이상 서버의 기존 세션은 현재 접속 중이라고 확정하지 않고 상태 확인 불가로 표시한다.
- 서버별 영속 이벤트 ID로 재전송 중복을 방지한다.
- 중앙 서버는 DB 트랜잭션 커밋 완료 후에만 수신 성공을 응답한다.
- 수집기는 기본 64MiB 이벤트 JSON 한도의 디스크 큐와 최대 60초 재시도 지연을 사용한다. SQLite 부가 공간은 별도다. 큐 포화 또는 256KiB 초과 이벤트 발생 시 새 이벤트를 버리고 누적 손실·공백 카운터를 증가시킨다.
- 발생 시각과 수신 시각은 UTC로 저장하고 화면에서 사용자 시간대로 표시한다.

## SQLite 운영

- WAL 모드를 사용하고 쓰기 작업은 단일 경로로 직렬화한다.
- 로그 저장, 관리자 설정 변경, 자동 삭제를 모두 짧은 트랜잭션으로 처리한다.
- 쓰기 대기는 유한하게 제한하며 과부하 시 수집기가 재시도할 수 있도록 응답한다.
- 서버·계정·시간 필터에 맞는 인덱스와 페이지 단위 조회를 제공한다.
- 명령 문자열 검색은 SQLite에 맞게 구현한다. PostgreSQL pg_trgm 계획은 적용하지 않는다.
- 보관 기간이 지난 기록은 작은 묶음으로 삭제한다. 파일 공간 회수 정책도 별도로 마련한다.
- WAL 체크포인트와 디스크 사용량을 관리한다.
- 실행 중 DB 파일만 복사하는 방식 대신 일관성 있는 SQLite 백업 방식을 사용하고 복원 검증을 수행한다.
- SQL 접근 코드를 분리해 PostgreSQL 전환 여지를 둔다. 전환 시 데이터 이관과 쿼리 수정은 별도 작업이다.

## 인증과 데이터 보호

- 관리자 인증은 만료되는 서버 세션과 HttpOnly 쿠키를 사용한다.
- 비밀번호는 검증된 비밀번호 해시 방식으로 저장한다.
- HTTPS 운영에서는 Secure 쿠키와 CSRF 방어를 적용한다.
- 수집기는 서버별 토큰으로 인증하며 토큰 폐기와 교체를 지원한다.
- 명령 인자의 알려진 비밀번호·토큰 패턴을 수집 단계에서 마스킹한다. 완벽한 민감 정보 제거를 보장하지 않는다.
- 일반 화면에서 수집 기록을 수정하는 기능은 제공하지 않는다.

## 검증 기준

- 실제 SSH 접속 성공·실패·종료 및 세션 연결을 검증한다.
- sudo 실행에서 로그인 계정과 실행 계정을 확인한다.
- 로그 회전, 수집기 재시작, 중앙 서버 재시작 및 네트워크 단절·복구를 검증한다.
- 커밋 후 응답 유실과 재전송 상황에서 중복 저장이 발생하지 않아야 한다.
- 실행 이벤트 조합, 세션 연결 불명 처리, 권한 없는 조회·수집 거부를 검증한다.
- 기록 수집 중 검색·자동 삭제 부하와 백업·복원을 검증한다.
- 실제 Linux 환경에서 검증하지 못한 수집 기능은 모의 데이터 검증과 구분해 보고한다.

## 미확정 환경과 용량

실제 서버 배포판, 서버 대수, 초당 이벤트 수는 아직 미확정이다. 최초 지원 배포판 제안은 Ubuntu 24.04 LTS이며 사용자 환경에 맞춰 확정한다.

중앙 서버 2 vCPU, RAM 4GB, SSD 50GB는 소규모 시범 운영의 초기 측정 기준이며 처리량이나 30일 보관 용량 보장이 아니다. 저장 지연, 검색 응답 시간, 디스크 사용량을 측정해 조정한다.

## 구현 순서

중앙 서비스의 실행 인터페이스는 루트 `Makefile`로 제공한다. `make up`은 빌드·백그라운드 실행, `make down`은 영구 볼륨을 유지하며 종료·제거, `make reload`는 재빌드·강제 재생성, `make status`는 컨테이너 상태 조회, `make help`는 사용법 표시다. `reload`에는 잠시 서비스 중단이 발생한다. 기본 Compose 경로는 `compose.yaml`이며 `COMPOSE_FILE`로 변경할 수 있다.

앱과 Compose 설정이 구현되어 `make up`으로 실행할 수 있다. 최초 실행 시 로컬 설정과 관리자 비밀번호 파일을 자동 생성한다. `make backup`, `make restore`, `make test`, `make integration`, `make agent`도 제공한다. 상세 사용법은 [README](../README.md)에 기록한다.

1. 저장소 구조, SQLite 스키마·마이그레이션, API 계약 구성.
2. 실제 Linux SSH·audit 로그 수집과 세션 연결 검증.
3. 수신 API, 영속 버퍼, 재전송·중복 제거 및 인증 구현.
4. 전체 현황, 접속·실행 검색, 세션 상세 및 서버 관리 화면 구현.
5. 보관 정책, 백업·복원, 설치·배포 문서 및 통합 검증.

## 활동 가독성과 프로세스 정보 확장

- 웹 기본값은 주요 활동이며 전체·보조 실행 전환, 제외 건수 및 분류 이유를 제공한다.
- 보조 분류는 알려진 프로그램·정확한 인자 조합으로 제한한다. 실패·결과 불명·권한 변경 실행은 유지한다. 수집 제외나 기록 삭제는 하지 않는다.
- API가 검색 조건과 분류를 페이지 분할 전에 적용한다. 요약과 항목은 같은 읽기 트랜잭션에서 조회한다.
- 긴 명령은 접고 펼친다. 프로세스 PID와 부모 PID는 nullable 정수로 저장한다.
- 스키마 1에서 2로 트랜잭션 이전하며 구형 수집기 및 버전 1 백업을 지원한다. 새 수집기 배포는 중앙 서버 갱신 후 진행한다.
- 프로세스 트리·반복 묶기·관심 활동 필터는 [후속 제안](activity-improvements.md)이며 아직 구현 범위에 포함되지 않는다.

## 관리자 계정 및 설치 확장

- MIT 라이선스 적용. 최초 관리자 ID/PW 지정과 추가 관리자 생성, 자신의 비밀번호 변경을 제공한다.
- 모든 관리자의 권한은 동일하다. 비밀번호 변경 시 해당 계정의 세션만 모두 폐기한다.
- 스키마 3은 인증 세션의 소유 계정을 저장한다. 버전 1·2에서 이전 시 기존 로그인 세션은 폐기하고 계정과 감사 기록은 유지한다. 복원 도구는 버전 1·2·3을 지원한다.
- 루트 `install.sh`는 Ubuntu 24.04 x86_64에서 APT 의존성 설치, 소스 다운로드·빌드, 기존 수집기 설치 스크립트 실행을 연결한다.
